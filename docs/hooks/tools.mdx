<Note>Tool hooks are experimental. Expect breaking changes while we iterate.</Note>

<Tip>
  **The easiest way to set up tool hooks is to ask Xum.** Just tell Xum what you want (e.g., "lint
  Python files after edits" or "block force pushes") and it will create the hook scripts for you.
</Tip>

Tool hooks let you run your own scripts before and after Xum tool executions.

## Block dangerous commands

Create `.xum/tool_pre` to validate commands before they run. Exit non-zero to block:

```bash
#!/usr/bin/env bash
# .xum/tool_pre - runs before every tool

if [[ "$XUM_TOOL" == "bash" ]]; then
  script="$XUM_TOOL_INPUT_SCRIPT"

  if echo "$script" | grep -q 'push.*--force'; then
    echo "❌ Force push blocked" >&2
    exit 1
  fi

  if echo "$script" | grep -q 'rm -rf /'; then
    echo "❌ Dangerous rm blocked" >&2
    exit 1
  fi
fi

exit 0  # Allow tool to run
```

```bash
chmod +x .xum/tool_pre
```

The agent sees your error message and can adjust its approach.

## Lint after file edits

Create `.xum/tool_post` to run validation after tools complete:

```bash
#!/usr/bin/env bash
# .xum/tool_post - runs after every tool
set -euo pipefail

[[ "$XUM_TOOL" == file_edit_* ]] || exit 0
file="${XUM_TOOL_INPUT_FILE_PATH:-}"
[[ -n "$file" ]] || exit 0

case "$file" in
  *.py)
    ruff check "$file"
    ;;
  *.ts|*.tsx)
    npx tsc --noEmit "$file"
    ;;
esac
```

```bash
chmod +x .xum/tool_post
```

<details>
<summary>Minimal formatter example (Go)</summary>

```bash
#!/usr/bin/env bash
# .xum/tool_post - runs after every tool
set -euo pipefail

[[ "$XUM_TOOL" == file_edit_* ]] || exit 0
file="${XUM_TOOL_INPUT_FILE_PATH:-}"
[[ "$file" == *.go ]] || exit 0

gofmt -w "$file"
```

</details>

Lint errors appear in `hook_output` and the agent can fix them.

<Note>
  `hook_output` is only shown in the UI when the hook produces output. For a cleaner experience,
  only print output when the hook has an effect—e.g., skip "Formatted: file" messages if the file
  was already formatted.
</Note>

## Set up environment

Create `.xum/tool_env` to configure your shell environment. This file is **sourced** before every `bash` tool call:

```bash
# .xum/tool_env - sourced before bash commands

# direnv
eval "$(direnv export bash 2>/dev/null)" || true

# nvm
# export NVM_DIR="$HOME/.nvm"
# [ -s "$NVM_DIR/nvm.sh" ] && source "$NVM_DIR/nvm.sh"

# Python virtualenv
# source .venv/bin/activate 2>/dev/null || true
```

<Note>
  Unlike hooks, `tool_env` doesn't need to be executable—it's sourced, not run. It only affects
  `bash` tools.
</Note>

## Reference

<Accordion title="Environment Variables">

All hooks receive these environment variables:

| Variable              | Description                                                      |
| --------------------- | ---------------------------------------------------------------- |
| `XUM_TOOL`            | Tool name: `bash`, `file_edit_replace_string`, `file_read`, etc. |
| `XUM_WORKSPACE_ID`    | Current workspace identifier                                     |
| `XUM_TOOL_INPUT_PATH` | Path to file containing full tool input (always set)             |

Xum flattens the tool input into `XUM_TOOL_INPUT_<...>` environment variables (see the appendix below). Fields longer than 8KB are omitted—use `XUM_TOOL_INPUT_PATH` for full access.

**Post-hook only (`tool_post`):**

| Variable               | Description                              |
| ---------------------- | ---------------------------------------- |
| `XUM_TOOL_RESULT_PATH` | Path to file containing full tool result |

Flattened result fields are available as `XUM_TOOL_RESULT_<...>`. Fields longer than 8KB are omitted—use `XUM_TOOL_RESULT_PATH` for full access.

</Accordion>

<Accordion title="Exit Codes">

| Exit Code | `tool_pre` behavior                | `tool_post` behavior                  |
| --------- | ---------------------------------- | ------------------------------------- |
| `0`       | Tool executes normally             | Success, output shown to agent        |
| Non-zero  | Tool blocked, error shown to agent | Failure, error shown in `hook_output` |

</Accordion>

<Accordion title="Hook Priority & Location">

Xum searches for each hook file in this order:

1. Project-level: `.xum/<hook>`
2. User-level: `~/.xum/<hook>`

This applies to `tool_pre`, `tool_post`, and `tool_env`.

For SSH workspaces, hooks execute **on the remote machine**.

</Accordion>

<Accordion title="Timeouts">

Hooks must complete within **10 seconds** or they're terminated. Long-running tools (builds, tests) don't count against this—only hook execution time.

Keep hooks fast—if you need longer operations, consider running them asynchronously or in the background.

</Accordion>

<Accordion title="Comparison">

| Feature        | `.xum/tool_pre`          | `.xum/tool_post`      | `.xum/tool_env`         |
| -------------- | ------------------------ | --------------------- | ----------------------- |
| **Purpose**    | Block dangerous commands | Lint/validate results | Environment setup       |
| **Runs**       | Before tool              | After tool            | Sourced in bash shell   |
| **Applies to** | All Xum-run tools        | All Xum-run tools     | `bash` tool only        |
| **Use case**   | Block force-push         | Run ruff/eslint       | direnv, nvm, virtualenv |

</Accordion>

<Accordion title="Provider-native tools">

Some models get tools that run on the provider's servers instead of in Xum. Hooks cannot see those calls.

- **Web fetch is always hooked.** In trusted projects (the only projects where hooks run), Xum gives every model its own `web_fetch`, so `tool_pre` and `tool_post` run for every fetch. Claude's native web fetch and Gemini's URL Context are not offered there.
- **Native web search is not hooked.** `web_search` (Claude, OpenAI, Grok), `x_search` (Grok) and `google_search` (Gemini) run on the provider, and hooks never run for them. Do not rely on a hook to restrict web search.

</Accordion>

<Accordion title="Appendix: Tool input env vars (auto-generated)">

Xum also provides flattened tool input env vars so hook scripts can stay compact.

- Scalars become `XUM_TOOL_INPUT_<FIELD>`
- Nested objects become `XUM_TOOL_INPUT_<PARENT>_<CHILD>`
- Arrays also include `..._COUNT` and per-index variables like `..._<INDEX>`

If a value is too large for the environment, it may be omitted (not set). Xum also caps the number of flattened env vars and array elements to keep hook execution reliable.

#!/usr/bin/env python3

import os, sys
